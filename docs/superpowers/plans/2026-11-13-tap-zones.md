# Tap Zones and Glyphs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace text hints (`^ tap: amp +`, `knob: hz`, `press long to exit`, `< back`, `ok >`) with glyphs drawn from one `TapZone` description that also does the tap hit-test.

**Architecture:** New `sdk/os/src/zones.rs` holds `Edge`, `Glyph`, `TapZone`. `ParamUi`, `SceneUi` and `Menu` define their zones as consts and use `hit` for input and `paint` for hints. Glyph position is computed from the screen circle, not hand-placed.

**Tech Stack:** Rust `no_std` + `alloc`, `embedded-graphics` (Rgb565), `libm`.

**Spec:** `docs/superpowers/specs/2026-11-13-tap-zones-design.md`

## Global Constraints

- Screen 360×360 round, centre (180,180), radius R=180.
- Glyph 16×16 px (`GLYPH`), colour `Rgb565::new(16, 32, 16)` (the old hint colour), no fonts, no text.
- Glyph corners stay inside the circle with 6 px margin: `hypot(corner) ≤ 174`.
- Zones: Top = `y<180` (`+`), Bottom = `y≥180` (`−`); Left = `x<120` (`<`), Right = `x≥120` (`>`).
- Text of `hz`/`amp` values and menu rows stays text.
- Tests: `cd /Users/noise/code/orbiversum/rust && cargo test --release -p orbiversum-os -p orbiversum-apps -p orbiversum-board-jc3636k718c`. `render-wav` is red on a clean tree (not ours) — ignore.
- Firmware must still build: `cd rust/boards/jc3636k718c/firmware && . /Users/noise/export-esp.sh && cargo build --release`.

## Review Focus

- A tap exactly on a zone boundary (`y=179/180`, `x=119/120`) goes to exactly one zone — pinned in Task 1 and Task 2.
- Scene animation redraws over a glyph's rectangle — the glyph must reappear, not get erased — pinned in Task 2.
- At the menu root the Back glyph is absent and a left tap changes nothing — pinned in Task 3.
- A tap with `y<0` or `y≥360` (garbage coordinates) is ignored by `ParamUi`, not treated as "top" — pinned in Task 2.
- A glyph never draws a pixel outside its `glyph_rect` (no bleed over neighbours / off-screen) — pinned in Task 1.

### Task 1: Zones module

Риск: обычный — рисование и геометрия под тестами, без конкурентности и контрактов.

**Files:**
- Create: `rust/sdk/os/src/zones.rs`
- Modify: `rust/sdk/os/src/lib.rs` (add `pub mod zones;` and `pub use zones::{Edge, Glyph, TapZone, GLYPH};`)

**Interfaces:**
- Produces (all `pub`, documented — crate has `#![warn(missing_docs)]`):
  - `pub const GLYPH: u32 = 16;`
  - `pub enum Edge { Top, Bottom, Left, Right }` (`Clone, Copy, PartialEq, Eq, Debug`)
  - `pub enum Glyph { Plus, Minus, Back, Forward, Knob }` (same derives)
  - `impl Glyph { pub fn paint(self, d: &mut Canvas<'_>, rect: Rectangle) }` — draws inside `rect` only (rect is the 16×16 square); used directly for `Knob`, which has no zone.
  - `pub struct TapZone { pub area: Rectangle, pub edge: Edge, pub glyph: Glyph }` with
    `pub const fn new(area: Rectangle, edge: Edge, glyph: Glyph) -> TapZone`,
    `pub fn hit(&self, x: i16, y: i16) -> bool`,
    `pub fn glyph_rect(&self) -> Rectangle`,
    `pub fn paint(&self, d: &mut Canvas<'_>)`.

- [ ] **Step 1: Write failing tests** in `zones.rs` `mod tests` (use a `Px` surface collecting drawn points, like `hal/src/menu.rs` tests):
  - `glyph_rect_corners_are_inside_the_circle`: for each `Edge`, `TapZone::new(any area, edge, Glyph::Plus).glyph_rect()` — all four corners have `hypot(dx,dy) ≤ 174.0` from (180,180), and the rect is `GLYPH×GLYPH`.
  - `glyph_rect_hugs_its_edge`: Top rect centre x=180 and y<40; Bottom centre x=180, y>320; Left centre y=180, x<40; Right centre y=180, x>320; and moving the rect one pixel further out would break the 174 limit (i.e. it is the maximal placement).
  - `hit_is_half_open_at_the_boundary`: zone `Rectangle::new((0,0),(360,180))` hits `(10,179)`, misses `(10,180)`; zone `Rectangle::new((120,0),(240,360))` hits `(120,5)`, misses `(119,5)`; negative `x`/`y` miss.
  - `every_glyph_paints_something_and_stays_in_its_rect`: for each `Glyph`, paint into `Px`; `!points.is_empty()` and every point is inside `rect`.
- [ ] **Step 2: Run** `cargo test --release -p orbiversum-os zones` — Expected: FAIL (module/items missing).
- [ ] **Step 3: Implement** `zones.rs` per the Interfaces. `glyph_rect`: along the edge's axis pick the largest integer distance `r` from the centre to the glyph's *outer* side such that `(r)² + (GLYPH/2)² ≤ 174²` (loop or `libm::sqrtf`), centre the other axis on 180. Glyphs: `Plus`/`Minus` — 2 px thick lines; `Back`/`Forward` — chevron of two lines; `Knob` — ~270° arc (`Arc` primitive) with an arrowhead triangle. Clip every draw to `rect` (`d.clipped(&rect)`), so nothing leaves the rect.
- [ ] **Step 4: Run** the same command — Expected: PASS.
- [ ] **Step 5: Commit** `feat(os): tap zones with glyphs placed inside the round screen`.
