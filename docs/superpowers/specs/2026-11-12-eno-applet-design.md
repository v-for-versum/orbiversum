# Апплет Eno: порт дрона Eno.scd на Rust

Дата: 2026-11-12. Ветка `scaffold`. Источник: `/Users/noise/code/github/northern-information/dronecaster/engine/drones/Eno.scd`
(«Music for airports», 73 строки SuperCollider). Платформа: `docs/superpowers/specs/2026-11-12-layered-rust-platform-design.md`.

## Цель

Eno звучит на плате JC3636K718C третьим апплетом (после Starlids и Sine), переключается из меню, узнаваем на слух при
сравнении с norns (как Starlids: на слух, не побитово).

## Ограничения

- Один апплет звучит за раз; Eno должен влезать в бюджет ядра 1 сам по себе: блок 128 кадров при 48 кГц, 2666 мкс.
  Целевая загрузка ≤ ~86% (≤ ~2300 мкс на блок) при работающем UI. Starlids для сравнения — 87%.
- Аудио-путь без аллокаций, без локов; память выделяется при создании апплета и освобождается при смене.
- f32 без деления и без `f64` в горячем пути (libm `sinf/cosf/expf/powf/exp2f` считают через soft-f64; f32-деление программное);
  приёмы и цифры — раздел «Что менять перед этапами 2–3» спеки платформы. Буферы во внутренней RAM.
- Случайность оригинала (`Rand`, `Dust`, `TChoose`, `Dxrand`) воспроизводить не нужно: тот же характер, детерминизм по seed.
  Побитовое совпадение с SuperCollider невозможно и не требуется.

## Критерии успеха

1. Узнаваем на слух (пользователь, A/B с norns) — решает пользователь на плате.
2. Загрузка ядра 1 ≤ ~86%, без пиков выше бюджета, без треска.
3. Хост-тесты: детерминизм по seed, независимость от размера блока, отсутствие аллокаций в `process`, конечность значений
   на длинном рендере (минуты), юнит-тесты блоков по формулам SC; после одобрения звука — golden-регрессия по своему зафиксированному рендеру.
4. Спека платформы обновлена замерами Eno.

## Архитектура

Без новых слоёв, шаблон Starlids:

- `rust/crates/blocks` — новые блоки (ниже), `no_std` + `alloc`, `tick` без аллокаций.
- `rust/crates/dsp/src/eno.rs` — голос `Eno`, реализует `dsp::Voice`; `hz` = корневая нота (по умолчанию 330, как в оригинале), `amp`.
- `rust/crates/applets` — `all()` получает третью пару `("Eno", VoiceApplet<Eno>, ParamUi)` после Starlids и Sine.
- Контрольный шаг 32 сэмпла, как у Starlids; расчёт по секциям с профайлером `dsp::prof` (строки `prof:` в логе, секции Eno свои).
- Секвенсор (Demand, Dust, TChoose) тикает на контрольном шаге по абсолютным позициям ⇒ звук не зависит от размера блока;
  точность моментов триггера ≈0,7 мс.
- Память: реверб ~40 КБ, остальное мало, итого порядка 80 КБ при ~194 КБ свободной внутренней RAM; всё во внутренней RAM.

## Новые блоки (`blocks`)

| Блок | Для чего в Eno | Заметка |
|---|---|---|
| `Dust`, `Impulse` (контрольные) | смена плоскости, ритм нот | на seed `Rng` |
| `Dseq`, `Dxrand`, `Demand`, `TChoose`, `TDelay` | выбор секвенций и нот | контрольная частота |
| `Decay2`, перкуссионная огибающая, `LagUD`, `EnvGen`-подобные | струна пианино, PolyPerc, плавный вход | |
| `Noise2` (LFNoise2); `Noise0/1`, `VarLagSine`, `SinOsc`, `Pulse`, `SawDpw`, `Biquad` уже есть | | |
| `RLPF`, `MoogFF` (аппроксимация), `Ringz`-резонаторы (для `DynKlank`), `CombL` | пианино, PolyPerc, DynKlank | |
| `FreeVerb` облегчённый | реверб | 4 comb + 2 allpass на канал вместо 8 + 4; решение принято заранее по CPU |

## Голос `Eno`

1. Пэд: 4 общих `SawDpw` на 8 голосов (у пар `i%4` одна высота и нулевая фаза ⇒ сигнал одинаков); у каждого голоса свои LPF,
   мини-delay (~1 мс, линейная интерполяция вместо кубической) и пан; огибающая плоскости (`planeenv`); два синуса (note-24, note-12).
2. `tanh` и стерео `MoogLadder` (как в Starlids, один проход, rational tanh).
3. `DynKlank`: 4 резонатора на канал на розовом шуме, частоты по нотам плоскости.
4. Пианино: шум (`LFNoise2` × `Decay2`) → 2 `CombL` (расстройка) → `RLPF` → `HPF`.
5. PolyPerc: `Pulse` → `MoogFF` с перкуссионной огибающей; `SelectX` между пианино и PolyPerc.
6. Финал: LPF, HPF 120 Гц, плавный вход (0.5 с тишины, 3 с нарастание), реверб, `amp`.

## Вехи и приоритет жертв

Прошивка и замер `prof:` после каждой вехи:

1. Пэд + Moog (ориентир ≈1750 мкс).
2. + пианино и PolyPerc (≈2150).
3. + DynKlank и реверб, итог ≤ ~2300.

Если выше бюджета: сначала упростить реверб (уже облегчён, ещё меньше линий, один канал считается, второй из него), затем DynKlank.
Решение пользователя (2026-11-12). Если и этого мало — отдельное решение пользователя (меньше голосов пэда, 6 вместо 8).

## Задачи (для плана)

1. Блоки A: секвенсор, шум, огибающие.
2. Блоки B: RLPF, MoogFF, резонаторы, CombL.
3. Блок: облегчённый FreeVerb.
4. Голос Eno: пэд + Moog (веха 1).
5. Пианино + PolyPerc (веха 2).
6. DynKlank + реверб + финал (веха 3).
7. Регистрация апплета, замеры, обновление спеки платформы.

## Не входит

Побитовая точность с SuperCollider; одновременная работа со Starlids; распределение работы по ядрам (ядро 0 занято UI/LVGL).

## Риски

- CPU: расчёт на пределе, зависит от замера; mitigated вехами и заранее выбранным приоритетом жертв.
- `MoogFF` и `FreeVerb` не побитово как в SC: проверка на слух.
- Realtime и unsafe в IRAM-группировках (как в Starlids) ⇒ высокий риск у задач 2–6, полное ревью.
